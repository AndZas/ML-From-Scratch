# Универсальная N-граммная модель

Дата: 2026-10-17  
Статус: практическое завершение раздела

## Моё понимание

N-граммная модель может работать с разным порядком `N`. Настройка задаёт порядок модели: биграмма имеет порядок 2, триграмма — 3, четырёхграмма — 4.

Чтобы предсказать следующий токен, модель использует последние `N - 1` токенов. Параметр `ngram` в моей реализации задаёт именно порядок модели, поэтому при `ngram = 4` контекст состоит из трёх предыдущих токенов.

Ключ таблицы переходов — кортеж из `N - 1` предыдущих токенов. Значение ключа — словарь возможных следующих токенов с их счётчиками. После подсчёта частот они переводятся в вероятности отдельно для каждого контекста.

## Как строятся переходы

Для каждого предложения в начало добавляется `N - 1` маркеров `<start>`, а в конец — один `<end>`. Начальные маркеры дают модели контекст, с которого она может предсказать первое слово. `<end>` становится возможным продолжением и позволяет модели закончить предложение.

Далее текст проходится окнами по `N` токенов. Первые `N - 1` токенов окна становятся ключом-кортежем, а последний — следующим токеном, который увеличивает счётчик для этого ключа.

Например, для порядка 4 окно можно представить так:

```text
(токен 1, токен 2, токен 3) → токен 4
```

## Как работает генерация

Генератор начинает с контекста из `N - 1` маркеров `<start>`. Он выбирает следующее слово среди вариантов для текущего контекста, сдвигает контекст: убирает самый старый токен и добавляет выбранный в конец. Так повторяется, пока не выпадет `<end>` или не будет достигнут лимит шагов.

Модель использует только последние `N - 1` токенов. Она не хранит всю историю уже сгенерированного текста и не понимает, что какое-то слово «уже было раньше».

## Что я увидел на своих данных

В моём примере внутри одной строки повторяется контекст `кот ест`, но после него в разных местах идут разные слова. Триграмма видит только `кот ест`, поэтому объединяет эти продолжения. Если она снова попадает в этот контекст, то может повторять переходы и ходить по циклу. Завершение доступно только там, где соответствующий контекст в обучающих данных переходил к `<end>`. Лимит шагов не даёт генератору работать бесконечно, но строка может закончиться по лимиту, а не по `<end>`.

Четырёхграмма учитывает на один токен больше. В этом корпусе дополнительный токен различает два места, где встречается `кот ест`, и помогает воспроизвести обучающую последовательность. Это не понимание смысла и не правило, что четырёхграмма всегда будет копировать данные: результат зависит от корпуса и от того, насколько контексты в нём повторяются.

В общем случае меньший порядок чаще объединяет похожие локальные контексты и может зацикливаться или собирать новые сочетания. Больший порядок различает более длинные последовательности, но чаще запоминает конкретные фрагменты и хуже обобщает, если для контекстов мало примеров.

## Что я сделал

- Обобщил подсчёт переходов так, чтобы порядок N-граммы можно было настраивать.
- Использовал кортеж переменной длины как ключ контекста.
- Настроил добавление нужного количества `<start>` и сдвиг контекста при генерации.
- Поддержал униграмму: при `N = 1` контекст пустой.
- Проверил работу модели на нескольких порядках, включая большие значения.

## Что важно помнить

- `N` — порядок модели; длина контекста равна `N - 1`.
- Униграмма имеет порядок 1 и не использует предыдущий контекст.
- Большое значение `N` само по себе не делает модель умнее: модель учитывает более длинные шаблоны, но может запоминать данные и не иметь достаточно примеров для каждого контекста.
- `<end>` позволяет завершить генерацию, но не гарантирует, что любой путь генерации до него дойдёт.
- Генератор может остановиться по лимиту шагов, если не выбрал `<end>`.
