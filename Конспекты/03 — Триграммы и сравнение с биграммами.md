# Триграммы и сравнение с биграммами

Дата: 2026-10-16  
Статус: базовый практический этап

## Моё понимание триграмм

Биграмма смотрит на одно предыдущее слово и считает, какое слово шло после него. Триграмма смотрит на два предыдущих слова и считает, какое слово шло после этой пары.

То есть триграмма хранит не просто переход `слово → следующее слово`, а переход от пары слов:

```text
(предыдущее слово 1, предыдущее слово 2) → следующее слово
```

Например, ключ `("кот", "ест")` может вести к словам `"рыбу"` и `"корм"`. Ключ-кортеж — это два слова контекста, а вложенный словарь хранит возможные следующие слова и их счётчики. Затем счётчики для каждого ключа отдельно переводятся в вероятности.

## Как я считаю переходы

Я передаю функции список предложений и обрабатываю каждое предложение отдельно. Для триграммы добавляю в начало два маркера `<start>`, а в конец — один `<end>`.

Два `<start>` нужны, потому что для первого предсказания модели требуется пара предыдущих токенов. `<end>` становится возможным следующим токеном и сообщает генератору, что предложение закончилось.

Для набора предложений:

```text
кот ест рыбу
кот ест корм
пёс ест мясо
пёс ест корм
```

часть переходов будет выглядеть так:

| Два предыдущих слова | Следующее слово | Счётчик |
| -------------------- | --------------- | ------: |
| `<start> <start>`    | `кот`           |       2 |
| `<start> <start>`    | `пёс`           |       2 |
| `кот ест`            | `рыбу`          |       1 |
| `кот ест`            | `корм`          |       1 |
| `пёс ест`            | `мясо`          |       1 |
| `пёс ест`            | `корм`          |       1 |

Поэтому после контекста `кот ест` у `рыбы` и `корма` вероятность по этому корпусу будет по `1/2`. После `пёс ест` такие же оценки будут у `мяса` и `корма`.

## Как генерируется предложение

Генератор начинает с пары `(<start>, <start>)`, находит для неё возможные следующие слова и выбирает одно с учётом вероятностей. Потом сдвигает контекст: выбрасывает самое старое слово и добавляет выбранное.

Например:

```text
(<start>, <start>) → кот
(<start>, кот) → ест
(кот, ест) → рыбу
(ест, рыбу) → <end>
```

Когда выпадает `<end>`, генерация заканчивается. Сами маркеры границ в итоговую фразу не входят.

## Что показало сравнение с биграммой

В биграмме после слова `ест` смешиваются продолжения из разных фраз: `рыбу`, `корм`, `мясо`. Модель видит только последнее слово и не различает, кто именно ест. Поэтому может собрать сочетание, которого не было в обучающих фразах, например `кот ест мясо`.

Триграмма различает контексты `кот ест` и `пёс ест`, поэтому в этом примере не смешивает их продолжения. Но корпус очень маленький: контексты почти полностью определяют исходные фразы, и генерация часто повторяет одну из них.

Это не означает, что триграмма всегда копирует предложения. Она выбирает продолжение только по двум предыдущим токенам. На большем тексте те же пары могут встречаться в разных местах, и модель будет обобщать только в пределах выученных локальных переходов.

## Что важно помнить про размер контекста

Для N-граммы порядок `N` означает, что модель использует `N - 1` предыдущих токенов, чтобы оценить следующий. Биграмма использует один токен контекста, триграмма — два.

Чем больше контекст, тем больше различий между ситуациями модель может сохранить. Но длинные контексты реже повторяются, поэтому данных для оценки каждого перехода становится меньше. На маленьком корпусе модель может запоминать длинные фрагменты; на большом ей всё равно доступен только фиксированный контекст из последних `N - 1` токенов.

Биграмма не выбирает «нелогичное» слово намеренно. Она просто не знает более ранний контекст. А триграмма учитывает на одно предыдущее слово больше, но сама по себе не понимает смысл и не знает грамматику за пределами статистики переходов.
